# v2.0 Addendums Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** On branch `v2.0-addendums`, fix two fuzzer crashes, resolve the two `vitest` security alerts, evaluate/merge the two Dependabot PRs, and rebuild the Web UI as a VESTA/OVITO-inspired report-forward workbench (Steel dark-first theme) that still runs on the Render free tier.

**Architecture:** Backend crash fixes route hostile input through the existing `§5 ParseError` contract (no behavior change for valid files). The frontend keeps every current Next.js route but wraps them in a new shared workbench shell (toolbar · sources rail · center · inspector · status bar); theming is a retune of the existing `data-theme` token system with the default flipped to dark. No `/v1` contract change.

**Tech Stack:** Python 3.11/3.13 (pydantic v2, numpy, ASE, defusedxml), Next.js App Router + React + Tailwind, vitest + Playwright, Docker Compose for e2e, ClusterFuzzLite/Atheris for fuzzing.

## Global Constraints

- **Spec:** `docs/superpowers/specs/2026-09-25-v2.0-addendums-design.md` (every task's requirements implicitly include it).
- **Records ship with the code** — update `docs/private/DECISIONS.md` (next free D-number) and the `docs/private/MASTER_SPEC.md` revision log in the same change (these are gitignored/local-only but still maintained), and the published `CHANGELOG.md`.
- **No AI attribution** in commits/authorship (local git hooks enforce this; **never** use `--no-verify`).
- **No silent data loss** — every augmentation is an Assumption + `supplied` entry; hostile input fails through `ParseError`, never an uncaught exception.
- **Loss palette is CI-guarded** — `--cb-*` tokens must stay AA-legible in *both* themes (`frontend/app/globals.contrast.test.ts`), always paired with icon + text label.
- **Python gate (run in the `.venv`) before any Python commit:** `ruff check .` → `ruff format --check .` → `mypy` → `lint-imports` → install toyfmt (`pip install --no-deps ./tests/fixtures/xtalate_toyfmt`) → `pytest`, on 3.11 **and** 3.13 (the numpy stub split trips mypy only on the 3.11 leg — see memory).
- **Frontend gate before any `frontend/` or `backend/` commit:** the vitest/typecheck/lint gate **and** the full Playwright e2e suite through Docker Compose **on this branch** (`XTALATE_MAX_UPLOAD_BYTES=1048576 docker compose up -d --build --wait`; Playwright vs `E2E_BASE_URL=http://localhost:3000` / `E2E_API_URL=http://localhost:8000`; `docker compose down -v` after). A green vitest run is **not** evidence e2e passes.
- **Schema stays `1.0.0`, package version is not flipped** here (publish/tag is the maintainer's step, D52). This is an addendum branch, not a release.
- **Terminology is binding** — reuse exact field/endpoint/component names; never rename silently.

### Task 1: POSCAR zero-atom refusal (`matmul` crash)

The discovery/parser crash `ValueError: matmul: ... (size 3 is different from 0)` comes from a POSCAR
whose atom counts sum to zero: `coords == []` → `frac` has shape `(0,)` → `to_cartesian(frac, lattice)`
does `(0,) @ (3,3)`. Refuse a zero-atom POSCAR through `ParseError` before the multiply.

**Files:**
- Modify: `src/xtalate/parsers/poscar.py` (add guard just before the `# --- coordinates` block, ~line 296)
- Modify: `tests/fuzz/seeds.py` (add a `poscar` tailored seed)
- Test: `tests/parsers/test_poscar.py` (unit refusal test) and `tests/fuzz/test_parser_fuzz.py` (already asserts the seed)
- Test: `tests/discovery/` (a discovery-path regression asserting `discover()` declines the same bytes)

**Interfaces:**
- Consumes: existing `_error(code, message, *, location=None, hint=None) -> ParseError` in `poscar.py`; `to_cartesian(fractional, lattice)` in `schema/cell.py`.
- Produces: a `POSCAR_MALFORMED` `ParseError` for any POSCAR with `n_atoms == 0`.
