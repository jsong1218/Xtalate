# v2.0 Addendums — Design Spec

**Date:** 2026-09-25
**Branch:** `v2.0-addendums`
**Status:** Approved for planning

## Overview

This branch bundles four independent workstreams requested together. Only the first
(a full UI/UX redesign) is creative work needing a design; the other three are
well-scoped fixes recorded here so the implementation plan covers them in one branch.

1. **UI/UX redesign** — rebuild the Web UI as a VESTA/OVITO-inspired, desktop-style
   scientific *workbench*, while keeping the hosted Render demo working within free-tier limits.
2. **Security** — resolve the two open GitHub Dependabot alerts (both `vitest` /
   `@vitest/mocker` path-traversal, medium).
3. **Fuzzing** — fix the reproducible crashes the ClusterFuzzLite `cflite-batch` job found
   (two distinct defects behind the "four artifacts").
4. **Dependency PRs** — evaluate the two open Dependabot PRs (#117, #118) and merge only
   those that do not break the current state.

Binding constraints from `CLAUDE.md`: the redesign is **presentation-layer only** — no
`/v1` contract change, no scientific-core change beyond the two crash guards. Xtalate is a
loss-aware converter, **not** a visualization-first app: the Conversion Report stays the
hero even though the visual language borrows from viz-first tools. The `--cb-*` loss palette
is CI-guarded (`globals.contrast.test.ts`) and must stay AA-legible in both themes, always
paired with an icon + text label (color is never the sole carrier of meaning).

## Workstream 1 — UI/UX Workbench Redesign

### Decisions (from brainstorming, all approved)

- **Layout: report-forward workbench.** Same dark docked shell as VESTA/OVITO, but the center
  is a tabbed content area where **Report** leads and Structure / Convert / Analysis / Compare
  are peer tabs — the 3D view is a first-class panel, never the whole stage. This honors the
  report-first mission and is the lightest option on Render (one center panel mounts at a time).
- **Theme: Steel dark-first + neutral-gray light toggle.** Dark (Steel — cool blue-gray
  surfaces, cyan-teal accent) becomes the default; light (neutral-gray Qt-style desktop) is the
  toggle. The existing `data-theme` mechanism is reused; only the token *values* and the
  *default* change.
- **Build strategy: keep routes, wrap in a shared shell.** The workbench chrome becomes the
  app layout; existing routes render into the center; tabs are real links. Preserves deep-links,
  SEO, SSR, and Render behavior, with the lowest e2e churn. Incremental.
- **Entry: workbench empty state** replaces the marketing landing — dropzone + "Try a sample"
  grid + recents. **No emojis** in the sample grid: use monochrome format badges / simple
  crystal-outline glyphs.

### Shell architecture

A new shared `AppShell` replaces the centered `max-w-5xl` container in `app/layout.tsx`.
It composes five persistent regions:

| Region | Component | Contents |
|---|---|---|
| Toolbar (top) | `components/shell/Toolbar.tsx` | Brand · Open/Upload · Convert▸ (target dropdown) · Validate · Repair▸ · (right) ⌘K · Formats · History · Docs · Theme toggle |
| Sources rail (left) | reworked `components/shell/SourceRail.tsx` | Session files with format badges; drop-to-add; collapsible |
| Center | `{children}` (routed pages) | Tabbed workspace — the only region that swaps per file |
| Inspector (right) | `components/shell/Inspector.tsx` | Contextual: summary chips + cell + provenance (Report); atom/cell props + legend (Structure); collapsible |
| Status bar (bottom) | `components/shell/StatusBar.tsx` | file · format · atoms · frames · job state · demo/auto-expire indicator |

- The center tab bar reworks the existing `components/shell/WorkspaceTabs.tsx` into the
  workbench tab strip, rendering real `<Link>`s to
  `/f/[file_id]/{report,structure,convert,analysis,compare}` (existing routes, unchanged).
- `components/shell/AppHeader.tsx` is superseded by `Toolbar` (its Formats/History/Docs/theme
  destinations move into the toolbar's right cluster; the skip-link stays in `layout.tsx`).
- `DemoBanner`, `DemoPrivacyGate`, and the demo indicator remain gated on
  `NEXT_PUBLIC_DEMO_BANNER`; a self-host renders none of the demo chrome.
- Global vs per-file surfaces: `/formats`, `/docs`, `/history` render into the center with the
  Sources rail present but Inspector collapsed/empty (they are not per-file). `/f/[file_id]/*`
  drives the full shell (rail selection, inspector context, status-bar facts).
- Inspector context is derived from the active route + the loaded file's already-fetched
  report/discovery data — no new API calls, no `/v1` change.

### Theme system

- Retune `app/globals.css`:
  - `:root` (light) → neutral-gray desktop values (cool light grays for surfaces, existing teal
    accent retained, dark text).
  - `:root[data-theme="dark"]` (dark) → Steel values (cool blue-gray surfaces `#12–#22` range,
    cyan-teal accent `~#2fb3c0` for chrome, keeping `--accent` teal for buttons).
  - Flip the default: `<html data-theme="dark">` and the no-flash script's fallback default to
    `dark` (persisted user choice still wins).
- Add workbench chrome tokens (e.g. `--wb-toolbar`, `--wb-rail`, `--wb-panel`, `--wb-status`,
  `--wb-hairline`) defined once, per theme.
- Preserve every `--cb-*` loss token; re-tune any whose contrast on the new *default* (dark
  Steel) surface would dip below AA, and extend `globals.contrast.test.ts` coverage to the new
  chrome-on-surface text pairs.
- Introduce a monospace scale (via the existing Tailwind config) for numeric/technical data
  (cell params, counts, residuals) — prose stays in the sans stack.

### Region behaviors & responsiveness

- **One-panel-at-a-time** center keeps free-tier memory low; SSR of each route is preserved.
- **Collapse rules:** below `md`, the Sources rail and Inspector collapse to icon rails / are
  hidden behind toggles; the toolbar condenses verbs into an overflow menu. The center is never
  hidden. Verified with the existing `e2e/responsive.spec.ts` (updated) + a mobile viewport.
- **Accessibility:** keep the skip-link first-focus, keyboard journeys (`e2e/keyboard.spec.ts`),
  and focus baseline (`globals.focus.test.ts`) green; the collapsible panels are keyboard- and
  screen-reader-operable (buttons with `aria-expanded`).

### Empty state (demo front door)

- Replaces `app/page.tsx`'s scroll landing with a workbench empty state: hero one-liner,
  large dropzone (format list + instance size cap from `/v1/limits`), a "Try a sample" grid
  using `components/samples/SamplePicker.tsx` (monochrome badges/glyphs, no emojis), and
  `RecentsStrip`. The ✓✗◆⚠ vocabulary folds into a compact legend near the dropzone.
- Live figures stay runtime-loaded (`export const dynamic = "force-dynamic"`), never baked at
  build.

### Out of scope (Workstream 1)

No `/v1` change, no new formats, no scientific-core change, no Mol* viewer rewrite (it becomes
the Structure tab panel unchanged), no new persisted state beyond the existing theme + recents.

### Testing & migration (Workstream 1)

- Routes are unchanged, so most of the ~35 Playwright specs keep working; update selectors only
  where chrome moved (header → toolbar, tabs, rail).
- Run the full e2e suite through Docker compose **on this branch** before any commit touching
  `frontend/`, per `CLAUDE.md` (`XTALATE_MAX_UPLOAD_BYTES=1048576 docker compose up -d --build
  --wait`, Playwright against `http://localhost:3000`, `docker compose down -v` after).
- Keep vitest unit/contrast/focus tests green; add tests for new shell components (Toolbar,
  Inspector, StatusBar collapse behavior).

## Workstream 3 — Fuzzing (crash fixes)

The `cflite-batch` scheduled job is failing on `main`. Its "four artifacts" are the four files
the latest run uploaded (2 crash bundles + 2 corpus bundles). The five crash inputs across
recent runs reduce to **two distinct reproducible defects**:

### Bug A — empty-positions `matmul` (`fuzz_discovery`)
- Trace: `discovery/engine.py:162 → parsers/poscar.py:336 → schema/cell.py:161 to_cartesian`
  → `ValueError: matmul: Input operand 1 has a mismatch in its core dimension 0 (size 3 is
  different from 0)`.
- Cause: a malformed POSCAR with a declared lattice but empty/blank fractional coords yields a
  `(0,)`-shaped array fed into `frac @ lattice`.
- Fix: in the POSCAR parser, refuse malformed/empty coordinate blocks with a clean
  `POSCAR_MALFORMED` `ParseError` **before** calling `to_cartesian`; defensively, `to_cartesian`
  should validate operand shape and raise a domain error rather than let NumPy raise a raw
  `ValueError`. The contract is "hostile input → clean refusal, never an uncaught crash."

### Bug B — unknown XML encoding (`fuzz_parsers`)
- Trace: `parsers/vasprun.py:655 parse → :682 parse_stream → :435 _read_header →
  xml/etree/ElementTree feed` → `LookupError: unknown encoding: <garbage>`.
- Cause: a vasprun.xml whose XML declaration names an encoding Python's codec registry doesn't
  know; ElementTree raises `LookupError`, uncaught.
- Fix: wrap the header/stream iteration so a `LookupError` (and other ElementTree parse
  exceptions from a hostile declaration) becomes a clean `PARSE_ERROR`/`VASPRUN_*` `ParseError`
  with a helpful message and location.

### Regression coverage
- Add the two minimized crash inputs as fixtures under `tests/fuzz/corpus/` (or the parser
  golden/negative suites) and assert each now raises the clean typed error, not a bare
  `ValueError`/`LookupError`.
- Re-run the fuzz harness locally (`pytest tests/fuzz/test_parser_fuzz.py`) and the standard gate.

## Sequencing

1. Land the fuzz crash fixes (Workstream 3) — self-contained, no UI risk.
2. Land the security bump (Workstream 2).
3. Evaluate/merge PRs (Workstream 4): merge #118 if green; report on #117.
4. Execute the redesign (Workstream 1) — the largest, done last so the e2e suite runs against a
   stable backend.

Each workstream is independently verifiable; the redesign gets the full plan → TDD → e2e
treatment. Records (D-log, MASTER_SPEC revision) are updated with the code per the standing rule.

## Risks

- **e2e selector churn** (redesign) — mitigated by keeping routes and running the suite before commit.
- **Contrast regressions** on the new dark default — mitigated by extending `globals.contrast.test.ts`.
- **Render free-tier cold start** — mitigated by one-panel-at-a-time and no bundle bloat.
- **PR #117 temptation** — explicitly gated: do not merge a failing PR even though it carries the vitest fix.
